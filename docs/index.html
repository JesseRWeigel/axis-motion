axis-motion

Animate OpenType variable font axes from a small timeline DSL. Exports to CSS @keyframes, the Web Animations API, and video.

About the type on this page No font file is embedded here. Shipping a whole variable font would add roughly a megabyte to this page, and a subset small enough to inline would still be a font committed to a repository that says it does not commit fonts. So the preview uses a system font stack: "Ubuntu Sans", Ubuntu, "Segoe UI Variable Text", system-ui, sans-serif. What you see depends on the fonts your machine has. The line above reports what this browser actually managed, measured rather than assumed. The axis values in the timeline were validated against UbuntuSans[wdth,wght].ttf on the machine that generated this page, which is where the numbers in the table below come from.

The complete set of axis tags present on this machine is wdth and wght. There is no opsz, no ital, no slnt, and no custom axis anywhere in this font set. That is worth stating plainly, because a tool that hardcodes the four common tags would look correct here and be wrong on the first font that carries a custom one. The parser reads whatever tags the table contains, and a test builds a synthetic font with GRAD and XPRT axes to prove it.

The timeline DSL

One statement per line. Blank lines and lines starting with # are ignored.

program    := line*
line       := directive | keyframe | comment | blank
comment    := ws* "#" any*
directive  := ws* name ws+ argument (ws+ argument)* ws*
name       := "font" | "text" | "duration" | "stagger" | "easing" | "name"
keyframe   := ws* "@" position ws+ settings (ws* "[" easing "]")? ws*
position   := number "%" | number ("ms" | "s")
settings   := setting (ws* "," ws* setting)*
setting    := tag ws+ number
tag        := <4 characters, [A-Za-z0-9 ], an OpenType axis tag>
number     := ["+"|"-"] digit* ["." digit*]
easing     := "linear" | "ease" | "ease-in" | "ease-out" | "ease-in-out"
            | "cubic-bezier(" number "," number "," number "," number ")"

The timeline driving the preview above

# axis-motion example timeline.
# Ubuntu Sans is the only variable family installed on this machine.
font     /usr/share/fonts/truetype/ubuntu/UbuntuSans[wdth,wght].ttf
text     "Axis Motion"
name     axisWave
duration 1200ms
stagger  60ms
easing   ease-in-out

@0%    wght 100, wdth 100
@50%   wght 800, wdth 75  [cubic-bezier(0.4, 0, 0.2, 1)]
@100%  wght 100, wdth 100

What that compiles to

/* axis-motion: axisWave */
/* font: UbuntuSans[wdth,wght].ttf */
/* axes animated: wdth, wght */
@keyframes axisWave {
  0% {
    font-variation-settings: "wdth" 100, "wght" 100;
    animation-timing-function: ease-in-out;
  }
  50% {
    font-variation-settings: "wdth" 75, "wght" 800;
    animation-timing-function: cubic-bezier(0.4, 0, 0.2, 1);
  }
  100% {
    font-variation-settings: "wdth" 100, "wght" 100;
    animation-timing-function: ease-in-out;
  }
}

What it refuses to do

A browser handed font-variation-settings: "opsz" 40 on a font with no optical size axis renders something and reports nothing. A value past an axis maximum is clamped just as quietly. The compiler checks both against the font's own fvar table and raises instead of emitting. These two messages are the real output of running those cases: 

$ axis-motion css bad-axis.tl
refused: axis "opsz" is not present in UbuntuSans[wdth,wght].ttf. Axes this font declares: wdth, wght

$ axis-motion css out-of-range.tl
refused: axis "wght" value 900 is outside the range declared by UbuntuSans[wdth,wght].ttf: allowed 100 to 800 (default 400)
